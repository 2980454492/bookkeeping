# 个人记账 (Bookkeeping) — 项目开发规范

## 项目概述

C++17 记账 HTTP 服务 + Web 前端，SQLite 本地存储，完全离线。
支持 PC 桌面端、WSL、Windows(.exe 交叉编译)。

## 目录结构

```
server/src/       C++ 源码（一个 .h 配一个 .cpp）
server/vendor/    第三方头文件（httplib.h, json.hpp）
server/frontend/  Web 前端（index.html / style.css / app.js）
scripts/          构建与启动脚本
```

---

## C++ 规范

**文件组织**
- 一个 `.h` 配一个 `.cpp`，文件名 `snake_case`
- 头文件用 `#pragma once`
- include 顺序：自身 .h → 项目内 .h → 第三方库 → 标准库，组间空行

**命名**
| 类型 | 风格 | 示例 |
|------|------|------|
| 类/结构体 | PascalCase | `Database`, `RecordQuery` |
| 函数 | camelCase | `queryRecords()`, `getCategories()` |
| 成员变量 | snake_case_ | `db_`, `page_size_` |
| 局部变量/参数 | snake_case | `db_path`, `date_from` |
| 常量 | UPPER_SNAKE_CASE | `MAX_RETRIES` |

**错误处理**
- 数据库：返回 `bool` / `std::optional<T>`，不抛异常
- `std::stoi` / `std::stod` 必须 try-catch
- 致命错误：`std::cerr` + `return 1`

**禁止**
- ❌ `using namespace std;`
- ❌ `new`/`delete`（用 RAII、STL 容器、智能指针）
- ❌ 硬编码绝对路径
- ❌ SQL 拼接不做转义（必须走 `Database::escape()` 或参数化）

---

## JavaScript 规范

- 用 `const` / `let`，不用 `var`
- 常量 `UPPER_SNAKE`，变量/函数 `camelCase`
- API 调用封装到 `API` 对象，DOM 操作封装到 `UI` 对象
- fetch 必须检查 `res.ok`

---

## Shell 脚本规范

- **必须** `set -euo pipefail`
- 用颜色输出函数：`info()` `warn()` `error()`
- 环境工具检查：每一步操作检查返回值，失败给原因+解决办法
- 编译错误捕获到临时文件，失败时 grep 错误行展示
- 路径用变量，禁止硬编码

## 注释规范

### 通用原则

1. **写"为什么"而非"是什么"**——代码已经说了"是什么"（`int port = 18080`），注释该解释"为什么是这个值"（`// 与 run.sh / README 保持一致`）
2. **注释是给未来的自己看的**——假设你三个月后打开这个文件，看到这行注释能否立刻理解当时的决策
3. **中文写注释**——业务逻辑、设计决策用中文，API 标识符（类名、函数名）保持英文
4. **代码修改时同步更新注释**——过期的注释比没有注释更危险

### 文件头注释

每个源文件必须以文件名 + 一句话职责开头，然后展开说明：

```
// filename.xxx — 一句话职责说明
//
// 详细说明：
//   - 这个模块负责什么
//   - 与哪些模块交互
//   - 关键设计决策
```

**C++ 头文件示例：**
```cpp
// db.h — SQLite 持久化层接口
//
// 职责：定义收支记录、分类相关的内存结构体，以及 Database 类的公开 API。
// 实现见 db.cpp；HTTP 层通过 handlers.cpp 调用本模块，不直接操作 SQL。
```

**JavaScript 示例：**
```js
// ═══════════════════════════════════════════════════════════════════
// app.js — 前端控制器
//
// 职责：通过 HTTP 请求与 C++ 后端通信，读写 DOM 更新界面。
// 所有数据交换均走 REST API (/api/*)。
// ═══════════════════════════════════════════════════════════════════
```

**Shell 示例：**
```bash
# ═══════════════════════════════════════════════════════════════════
# 脚本名 — 一句话用途
#
# 用法:
#   ./scripts/xxx.sh arg1       # 场景说明
# ═══════════════════════════════════════════════════════════════════
```

### 段落分隔

用视觉分隔线将长文件按职责划分为逻辑段落：

| 语言 | 分隔线 | 用途 |
|------|--------|------|
| C++ `.cpp` `.h` | `// ── 段落名（中文） ──` | 函数组、逻辑阶段 |
| C 宏块注释 | `/** Doxygen */` | 公开 API 文档 |
| JavaScript | `// ── 段落名 ──` | 全局状态 / API 封装 / UI 操作 |
| Shell | `# ═══` 或 `# ──` | 步骤/章节边界 |
| CMake | `# ── 段落名 ──` | 依赖 / 源文件 / 构建目标 |

### 公开 API 注释（C++）

Database 类的公开方法用 Doxygen 风格：

```cpp
/** 查询收支记录列表，支持多条件筛选、分页、排序 */
RecordListResult queryRecords(const RecordQuery& q);

/** 删除一级分类，同时级联删除其下所有二级分类 */
bool deleteCategoryL1(int id);
```

### 行内注释

```cpp
// ✅ 好——解释了为什么
int port = 18080;           // 与 run.sh / README 保持一致
sqlite3_exec(db_, "PRAGMA journal_mode=WAL", ...);  // WAL 允许读写并发

// ✅ 好——标注了注意事项
std::string name;           // 分类名以 TEXT 冗余存储，改分类名不会回写历史记录

// ❌ 坏——重复代码
int port = 18080;           // 设置端口号为 18080
i++;                        // i 自增
```

### 禁止

- ❌ 注释掉的代码块（用 git history 回溯，不要留在源码里）
- ❌ `/* */` 多行注释在函数体内部（用 `//`，保持风格统一。`/** */` 仅用于 Doxygen）

### 强制规则

**新增文件或功能时，必须添加注释，否则视为未完成：**

- 新文件 → 必须有文件头注释（文件名 + 职责 + 关键设计说明）
- 新函数/方法 → 必须有 Doxygen 或行内注释说明用途、参数、返回值
- 新类/结构体 → 必须有注释说明它代表什么、哪些模块使用
- 新的设计决策 → 必须写"为什么"注释（为什么选这个方案而非其他）
- 新的段落 → 用 `// ── xxx ──` 分隔线标注逻辑分组


- 提交信息：`【类型】描述`（类型：新增/修改/修复/优化/重构/文档）
- 一个提交只做一件事
- 不提交构建产物（`build/` `build-mingw/` `dist/`）
